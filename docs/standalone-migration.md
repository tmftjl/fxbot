# FxBot 独立运行时改造

## 目标与边界

将 FxBot 从 NoneBot 插件改造成独立应用：启动、生命周期、事件模型、消息分发、插件注册、
平台连接和后台任务由 FxBot 自己控制，最终运行、安装、测试都不再依赖 NoneBot 及其插件。

不重写数据库、HTTP、Web 服务等通用库，不复制一套完整的 NoneBot，不承诺兼容第三方 NoneBot 插件。
只实现现有业务实际需要的能力。现有配置、数据、权限、会员、AI、记忆和控制台尽量保留。

采用直接替换路线，不建立 NoneBot 桥接层或 Matcher 兼容外壳。
新协议层直接解析原始事件、编码协议动作，新业务直接使用自有事件和路由。
尚未替换的模块可以暂时保留，但不接入新核心的运行链路；不要求每轮都维持旧入口可运行。
在现有适配层中继续调用 NoneBot Bot，不算完成协议接入独立化。
代码注释与文档字符串只描述功能和约束，不写改造背景；依赖审计和工程计划单独记录。

4. 运行针对性测试和仓库静态检查，区分通过、失败、未执行及原有问题。
5. 更新本文件进度，交接修改内容、验证结果、风险和下一步。
6. 只有验收通过才标记阶段完成；跨轮未完成工作继续保留，不重新起炉灶。

默认不自动提交、推送或启动生产服务。需要阶段提交时先明确授权，提交只包含本轮相关改动。
架构原则以本文件为迁移目标；具体实现以源码为准。替换了稳定边界后同步更新对应开发规范，
不提前让仍运行的旧代码失去适用规则。

## 分阶段路线

### 0. 依赖审计与回归基线

- 扫描直接和间接依赖：导入、动态加载、入口元数据、注入参数、上下文、异常控制流、调度与运行钩子。
- 区分日志等机械替换项与 Matcher、平台连接等行为替换项；不能用导入次数估算迁移难度。
- 列出实际使用的命令、通知、会话状态、优先级、阻断和插件加载行为。
- 盘点现有测试的启动方式、通过情况、环境依赖和覆盖缺口，不把测试失败全部归因于迁移。
- 盘点已实现与实际使用的平台，再确定首个端到端试点及其他平台的迁移顺序。

验收：产出依赖清单、最小功能兼容清单、可复现测试命令和已知失败；未验证能力明确标注。

### 1. 无框架核心契约

- 根据现有用法定义必要的事件、消息段、目标、会话、Bot 接口与平台能力错误。
- 明确平台、Bot、群和用户标识的命名空间，避免迁移后跨平台数据串用。
- 自有协议层把平台原始协议数据解析成核心对象，不接收 NoneBot 运行时对象。
- 将日志、路径及进程配置的隐式框架依赖移到边界，保留原有配置兼容和热加载语义。
- 保证导入新核心不触发根包的旧启动入口，也不要求初始化 NoneBot。

验收：在没有安装 NoneBot 的隔离环境中可导入并测试新核心；协议解析和并发上下文隔离有测试。

### 2. 自有消息分发与插件注册

- 为实际使用的命令、正则、消息和通知实现注册与分发，不追求复刻所有 `on_*` 接口。
- 明确定义预处理顺序、权限检查、优先级、同级执行、阻断、异常和会话清理语义。
- 把现有参数注入、`send`、`finish` 及需要保留的会话交互逐项迁移，禁止仅改导入名伪装兼容。
- 先迁一个简单命令，用测试事件验证，不一次性批量改造全部子插件。

验收：纯核心测试覆盖命令、权限拒绝、阻断和异常；同一测试事件不会被旧新两套路由重复处理。

### 3. 独立应用入口与任务生命周期

- 自主管理启动、关闭、Bot 注册表、后台任务与共享资源，替换 NoneBot 调度插件依赖。
- 控制台接收显式应用对象，不再自行通过 `get_app()` 查找宿主。
- 保留配置先于业务、模型先于建表、会员门禁先于业务处理等行为约束。
- 包布局、命令行入口、依赖声明和资源打包一起验证，暂不只为改名搬动所有文件。

验收：不初始化 NoneBot 也能启动控制台；正常关闭、启动中途失败、重复初始化和任务取消有测试。

### 4. 首个平台的独立端到端闭环

- 自行实现选定平台所需的连接、鉴权、事件解析、API 请求关联、超时、断线恢复和发送。
- 接入核心分发，跑通接收、会员门禁、权限、命令或 AI、回复、统计和关闭。
- 通过协议夹具和本地模拟服务验证，再使用获授权的非生产账号做真实连接验证。

验收：试点平台的独立进程不加载 NoneBot；错误鉴权、断线、请求超时、离线发送和不支持能力有覆盖。

### 5. 完整业务与其余平台迁移

- 逐批迁移会员、AI/记忆、系统控制、定时任务、控制台 Bot 操作及内置子插件。
- 每批补充行为对照测试；迁移 AI 与子插件前读取各自专项规范。
- 将消息统计从框架猴子补丁迁至自有收发边界，避免漏计、重复计数和重试误计。
- 迁移其他现有平台；任何不再保留的能力必须先获得明确同意，不能静默删除。

验收：功能兼容清单逐项关闭；数据兼容、权限隔离、会员故障拒绝、续费恢复通路和 AI 历史一致性通过。

### 6. 清理依赖与独立交付

- 删除被替换的 NoneBot 入口、运行依赖、调度插件依赖及测试中的框架初始化。
- 检查源码、打包元数据、脚本、文档和依赖树，区分历史描述与实际运行依赖。
- 更新安装、配置、启动、平台接入、升级与数据恢复说明。

验收：干净环境不安装 NoneBot 即可安装、测试和运行；受支持平台完成回归；旧数据迁移与恢复已演练。
