# 审查修复与设计收敛清单

本轮直接替换接口，不提供旧名称转发或双路装配；不新增多轮会话等功能，不迁移业务数据格式。
普通共享业务对象、请求文件清理、异步操作后的权限和连接复查均保留。

## 正确性

| 审查项 | 实现与回归 |
| --- | --- |
| 非法权限会放宽限制 | 严格等级、场景、开关和名单结构；无效保存返回 400，原文件不变；test_refinement、test_console |
| 动作关闭二次取消 | 每个请求共享取消状态并等待清理；ActionCancellationTests |
| 子任务继承过期事件 | EventContext 有明确有效期，QQ 不再沿用过期被动回复 ID；ContextTests、test_refinement |
| 漏掉聊天测试 | tests/chat 成为正式测试包；移除旧 NoneBot 辅助文件和配置测试中的引用 |
| Python 版本声明不符 | requires-python 和 Ruff 目标统一为 3.11，保留原生超时和 ExceptionGroup 契约 |
| QQ HTML 503 停止网关 | 先判断 HTTP 状态，再解析成功正文；失败保留状态用于既有退避，业务写入不自动重试 |
| 插件安装留下半成品 | 全部定义和路由名称先校验；单个运行实例安装也先预检，失败不新增路由或资源 |
| 子任务创建阶段泄漏 | 迭代与创建均纳入清理范围；迭代器中途失败回收已创建任务 |

回归期间另发现 QQ 接收截止时间已过但 ACK 已缓冲时的误超时；接收任务现在先得到读取机会，
空队列仍超时并回收读任务。两种情况均有确定性测试，不靠增加测试时限通过。

## 设计

1. 应用服务使用 ApplicationServices；当前事件使用 EventContext / current_event_context。
   HandlerContext 和 TaskContext 通过 app_services、scope 区分应用依赖与插件服务缓存。
2. 核心命令、聊天、会员、控制台及目录插件统一使用 Matcher 声明和 bind_matchers 装配。
   Router 保留为底层执行与测试入口，不再为业务手写另一套声明流程。
3. MatchResult 保存参数、捕获组、命名组和命令词；直播和日报不再重新匹配命令正则。
   匹配构造共享，优先级分组在注册变更时更新。
4. 公开创建函数显式声明参数类型；内建处理参数在注册时编译绑定，未知类型提前失败。
   未引入任意业务对象的依赖注入容器。
5. MatcherOptions、匹配函数只读，加载后不能增添处理器；执行状态独立于声明。
6. 通用动作错误在 core.errors；配置订阅直接依赖 configuration。
   网页聊天和控制台访问命令由装配根管理，聊天、会员不再持有控制台功能。
7. 直播复用普通命令对象并直接绑定方法，不在每次调用中创建临时转发对象。
8. 记忆管理分为 HTTP 适配、应用用例与查询投影；应用错误使用语义枚举，由路由转换 HTTP 状态。
   表单声明是独立纯数据模块，不因数据量大而引入控制器或表单类层次。
9. 控制台从已加载插件的通用扩展取得配置页，不再扫描执行文件；配置与 UI 共享 defaults.py。
10. 权限流程明确分为强制拒绝、主人豁免和逐层普通规则，无策略类型特判和重复决策。
    配置代理提供 validate/snapshot/restore，事务不再修改代理私有状态。

## 验证边界

- 核心隔离测试不加载第三方包；默认发现包含聊天和配置测试，不用删除有效测试规避失败。
- 记忆模块拆分对 82 个函数作规范化语法树对照，检查租户过滤和查询行为未随文件移动漂移。
- 类型检查限定核心、四个平台客户端和相关错误／权限边界，不宣称整个业务仓库严格类型化。
- 最终 522 项默认发现测试、142 项核心隔离测试通过；27 个相关模块通过 Python 3.11 目标类型检查。
  sdist/wheel 及独立安装模拟验证通过，逐文件检查产物源码一致；没有提交、推送或部署。
- 过程中旧直播测试夹具未隔离共享对象，曾触发一次非预期公开直播查询；已停止该运行并修正夹具。
  最终协议与安装验证使用隔离数据和模拟服务，没有使用真实 Bot。
